# Issue 驱动工作流

## 日常阅读

一篇论文一个专属原始阅读会话、一个 Paper Issue。Issue 保存论文入口、必要进度与问题，不保存用于恢复理解的累计模型；不要求每句创建 Issue、PR 或日志。分析质量见[分析协议](../learning/source-first-sentence-reading.md)，会话边界见[会话与进度](../learning/reading-sessions.md)。

原会话用其已有上下文继续，不把 Issue 当每次启动的控制面。新会话不能根据旧记录续读；历史 READING STATE、checkpoint、handoff 及其 next_action 仅供追溯，不执行。

## 进度更新与并发

需要保存时按[进度规则](../learning/reading-sessions.md#何时保存)更新必要记录。覆盖 Issue 正文前重读，发现其他执行者的新变化不覆盖；写后回读确认。不维护“完整状态 comment → 正文指针”的恢复协议，不为保存进度复制完整分析。

论文身份、授权范围、精确停点与历史失败仍须如实保留。历史引用使用已确认存在的 blob/完整 commit/path，不指向 main 中已删除路径；删除恢复能力不等于删除历史证据。

## 仓库修改

维护在独立会话处理。只有具体 Source 故障、重复分析问题或规则/代码修改才建一个有界 Task；普通阅读不套工程流程，也不为验证维护重新读取论文。

```text
明确修改范围 → 独立分支/PR → 自审或所需 review + CI → 合并及对应检查 → 简短结果
```

只执行本次代码或文档修改需要的检查，不叠加独立会话试次、学习者测验或 Profile stable 门禁。通过的固定候选不因换会话重测。分析质量以具体语义问题审查，不用 CI PASS 代替。

## Task closure 证据门禁

此节只用于工程/文档修改，不用于每句阅读。

完成报告记录：base/candidate、PR、实际 review 与该候选检查链接、merge SHA、对应 main 检查、剩余限制、最终状态。自审写自审，review requested 不等于独立批准；没有运行的检查不称 PASS。

完整收尾证据集中保存在 Task 正文，PR 描述说明变更与验证并链接 Task；评论仅记录必要的新事实或更正，不重复整份报告。已有历史记录保持原样，不因这条约定删改。

未合并为待合并；已合并但必要检查未完成为 `merged-awaiting-verification`。关闭 Task 前回读 body/state/owner，释放 owner，下一动作不能仍指向已完成项。保留历史失败，不把取消需求改成测试成功。

遗留分支、已取消的实验需求与当前交付分别处理，不把它们自动变成阻塞。不得为了清理分支扩大权限或用 delete_file 冒充删除 ref。

## 已移除的流程

跨会话恢复、交接重建、持久化累计模型、训练、评分、预测锁定/揭示对照、盲恢复及跨仓库知识导出不属于本仓库功能，不保留可选入口。旧任务中的出题、等待作答、试次或稳定化 next_action 已停止适用；历史结果不变，取消不等于测试通过。

GitHub 只保存规则、论文入口、必要进度和问题，不是 canonical Source。原文缺失不能用旧评论补造，公开仓库不镜像整篇论文。
