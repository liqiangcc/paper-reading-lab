# Source-First 逐句分析协议

当前契约：`source-first-analysis/v2`。唯一目标是提供基于已知信息、逻辑连贯、层层讲透的 AI 逐句分析，让用户通过持续阅读自然学习分析方法。

## 唯一日常流程

```text
当前原文 → 忠实释义 → 有依据的连贯分析 → 当前句结束
```

用户通过持续阅读、回看或追问学习；分析深度由 AI 负责。已退役功能统一见[工程工作流](../workflows/issue-driven-workflow.md#已移除的流程)。

一篇论文在原始专属会话中持续分析；原文、推导过程和追问共同构成理解上下文。不提供跨会话恢复或交接重建。当前会话关键前文不可用时明确缺口，不靠 Issue 摘要、旧答案或记忆拼接后宣称连续理解。

## 分析必须做到什么

**忠实与明确。** 保留原文对象、指代和“可能、通常、仅在”等限定；必要术语就地解释，翻译不夹带机制推论。

**关系与增量。** 说明当前单元如何承接、对比、回答或限制已读前文，以及新增或修正了什么。普通句只接必要局部；关键机制句让零散设计闭环时，重组所需的全部已揭示前文。每次回接和重复都须带来新的结构理解，不能只贴关系标签或机械复述。

**依据与连接完整。** 从对象和线索，经必要前提与区别得到结论，后一层承接前一层。当前单元包含的条件、术语、数量与限定都要解释到足以理解；对 because / therefore / but 等关系讲清中间连接，不能只拆其中一项就收束。额外前提显式提出，箭头不代替理由，先后顺序不冒充因果。

**事实、推论和未知可辨。** 重要判断可追溯到已读 Source，或注明推论及成立条件；信息不足时解释缺口。不能编造作者动机、用观察结果冒充因果证明，或为模型完整而关闭开放问题。

**深度服务于理解。** 关键机制讲透，低信息过渡简短；删去无关背景，不删成立条件和中间理由。分析应连贯可读，不能以翻译、术语或结论代替解释，也不把流畅当作能力提升的证明。

## 默认呈现：首版高密度机制闭环风格

默认采用**高密度、动态编号、机制闭环型逐句分析**。以下只定义输出组织方式，质量依据见上节；结构由当前内容决定，不套固定字段表。

这里的“闭环”包括系统论文的机制连接，也包括概念论文的论证关系连接：概念区分、对象范围、限定、对立或因果都可能改变模型。没有公式或组件不代表信息少。不能把概念论文默认压成“释义 → 承接上一句 → 泛化 Unknown”；也不能为了闭环制造原文未给出的因果或算法。

### 关键机制句的展开程度

当当前单元把此前两个或更多独立机制接成可解释的路径，或使已有公式/参数第一次进入实际协议时，应展开这条连接：先说明局部操作，再分别解释它改变的职责、参数用途或推进方式，最后重建有依据的整体路径。不能把这些不同层次压成一句“因此形成闭环”。只展开当前 Source 支持的层次，不要求每句具有相同维度。

动态编号用于让每一个真实理解问题有独立展开空间。每节先点明问题，再带读者看已有依据、连接理由和当前新增的理解；短句、短段和留白帮助逐层前进，不机械拆碎每句话。可用“前面知道……现在这个值用于……”等具体承接，避免只堆抽象结论。

关键连接适合路径表达时，先画局部图；多个局部在本句连通时，再画整体图。不同层次的图应各自解释公式、职责、协议或系统路径的新增关系，不能用一张总图省略中间理解，也不能重复同图凑密度。事实不足的边界应突出说明；形成可迁移方法时再独立提炼。普通句保持局部解释，过渡句可以短；不固定九节、字数或图数。

建立或切换风格时，同步阅读同一 `contract_source_commit` 下的[完整展开示范](examples/mechanism-closure.md)，用于校准分层颗粒度、局部/整体图和引导节奏；同会话已读不重复加载。示范是虚构材料，不是任何 Paper 的已揭示前文，不得用于补论文事实。下面的批处理示范单独说明推导颗粒度，不能替代完整呈现参照。

同时阅读[概念与论证展开示范](examples/argument-closure.md)，校准如何把同样的深度用于概念边界和论证关系。用户确认的真实样本及其使用边界见[维护参考说明](examples/style-reference.md)；它不是日常自动加载入口，不因被收录就成为允许阅读的 Source。

还要阅读[输出版式示范](examples/output-format.md)，校准下一节的三档输出、编号点展开顺序、依据类型、问题账本、本句分析动作与一行停点。它同样是虚构材料，不得用于补论文事实。

### 从学习目标出发：让分析方法可见

逐句分析的最终目标不是让读者记住论文结论，而是让读者在持续阅读中看到并逐渐掌握“根据已有信息作出有依据的判断”的方法。清楚易懂只是前提：如果只呈现分析结论，读者学到的多是论文内容。因此在不出题、不评分的前提下，输出还要让分析过程可见。

**按信息量分三档。** 档位由当前单元在论证中的实际作用决定，不由句子长短决定。

- **过渡档**：标题、导览句、作者与元数据。原文、翻译，加一两句说明它在文中的作用；不编号，不写依据类型或问题账本。
- **普通档**：补充、举例、限定。总判断加 2–4 个编号点；关系不直观时才画图。
- **关键档**：把两个以上已揭示节点接成闭环，或第一次给出需求、机制、证据。完整展开，先局部后整体，最后用带短语的前文引用重建本会话已揭示的整条论证链。

**编号点按“线索 → 问题 → 依据 → 结论”展开。** 先指出原文中触发问题的词或结构，如转折词、限定词、数字或与前文的张力；再把问题说出来；然后给出依据，即当前句、已揭示前文或标明的背景；最后给结论。问题先于答案出现，读者在看到答案前会自然先想一步。这是组织方式，不是向用户提问或测验。

**四条推理约束。**

1. **先局部，后整体。** 先讲清当前句自身的推理，再回接前文；整条链放在最后。
2. **箭头必须有理由。** 原文没写出的中间前提要显式补出并标〔推论〕，不能用箭头或“因此”跳过。
3. **引用前文附短语。** 写“¶1 s2（旧流程每晚核对一次）”，不只写编号或位置，读者不需要回翻。
4. **限定词全程一致。** “主要”“往往”“可能”等限定在后续推理中保持原有强度，不能升级为“缺少”“不能”“一定”。

**依据分类型。** 这是 Known / Derived 的细分，只标在需要区分的地方，不逐句铺满：〔主张〕作者断言但未给依据；〔经验〕作者报告的实际使用；〔实验〕作者报告的实验或试运行结果；〔引用·未核〕依赖本会话未读取的参考文献；〔推论〕AI 在明示条件下推出；〔背景〕理解当前句必需的通用概念。

**问题账本。** 当前单元回答、修正或推翻了前文提出的问题时，写明对应位置和问题；新开的问题、仍待检验的推论简短列出。只列与当前单元有关的条目；段末或节末可汇总一次仍未回答的问题。它是本会话内的阅读组织，不是持久化累计模型或跨会话恢复资产。

**本句分析动作。** 当前单元确实用到可迁移的分析或设计方法时，在末尾用一两句为这一步命名，并说明什么时候可以用，例如“张力检测：两处说法看似冲突时，先找能让两者同时成立的条件，再把条件当作待检验假设带到后文”。没有真实方法增量时省略；同一方法再次出现时简短回指，不重复长篇说明。

### 增量要求：不是元素齐全就算讲透

- **句内层次。** 先辨认当前句真正施加的定义、量词、对象范围、限定和关系，再解释它们怎样共同成立。不只抓住一个中心词；也不按每个词机械分节。
- **前文回接。** 回答“此前怎样理解，现在哪一部分改变，依据是什么”。当前句重新连接较早的已知节点时，要取回必要的本会话前文，不只复述上一句。概念论文可以是评价对象、责任边界或论证层级改变，不必伪造消息流。
- **图的增量。** 每张图回答一个新结构问题：对象包含关系、限定范围、局部连接或整体路径。换方向、换排版的同一关系不算新图。箭头必须有文字解释其含义，不能把并列、关联或假设画成已证因果；若文字已经清楚，省略图。
- **未知的定位。** 能定位时，写清“已知 A、已知 B，但尚缺哪种依据才能从 A 连到 B”；单个节点的定义、数量或条件未知也可直接说明，不强凑两节点图。不因知道两个现象就假定它们有因果。Unknown 不应每句重复“具体是什么、为什么、如何实现”，要说明这项缺口限制了哪条当前结论。
- **完整而不堆叠。** 用解释把前提、区别和结论接起来。相邻小节若只换术语重复同一判断，应合并；若删掉会丢失一个成立条件、排除的误读或模型变化，则保留。参考样本的编号数、图数和长度不是目标。

典型节奏是：

```text
位置：Section / Page / paragraph / sentence / normalized_range

当前原文
必要的 PDF 抽取修正说明
中文翻译

一句总判断：
当前 SourceUnit 在论证中做了什么

1. 线索 → 问题 → 依据 → 结论
2. 下一个真实问题，同样展开
3. ...
   → 每个编号由当前句的信息和机制关系决定
   → 不是固定“字面/关系/增量/模型”字段

必要时：
- 回接前文，引用时附短语
- 画局部图，关键句最后再画整体路径
- 给出 Before / After、Problem → Mechanism → Effect
- 标注依据类型，区分 Known / Derived / Unknown
- 问题账本：本句回答了什么、新开了什么、什么待检验
- 本句分析动作

最后：
Current revealed position（一行）
```

具体要求：

- **原文与翻译先行。** 展示当前 exact re-read 的 canonical SourceUnit，外语随后给忠实中文翻译，中文不重复翻译。PDF 换行、断词、空白等噪声仅可做不改变字词和语义的排版整理，并明确说明；不能补词、改写或合并多个 provider unit。
- **位置要可靠，不猜正文计数。** 可展示论文、Section、Page、paragraph、sentence、normalized_range、effective_kind、degradation；“第 N 条正文句 / Section 总第 M 条正文句”只有本会话已有可靠计数时才展示，缺失时省略。
- **先给当前句一个总判断。** 在详细拆解前，用一两句话说明当前句的论证作用，例如“把前面几条机制串成循环”“把 OS 能力落回 Kafka 实现”“把 baseline 成本变成可比较数字”。这个判断必须由当前句和已揭示前文支撑。
- **动态编号，不固定字段。** 对有实质信息的 SourceUnit，按当前句真正产生的理解问题动态生成 `1、2、3...`，每个编号按“线索 → 问题 → 依据 → 结论”展开。编号标题可以是“前面的 next offset 现在真正用起来了”“Index → Segment 的映射”“但当前不能推出 Broker 完全无状态”等；不能机械填 `字面 / 前文 / 增量 / 模型` 五个槽位。
- **用图组织机制闭环。** 空间关系、层级、数据流、Before/After 或端到端路径用图更清楚时，主动画简洁 ASCII。Source 足够时可呈现 `Problem → Baseline → Cost → Existing Capability → Decision → Mechanism → Effect → Boundary` 等实际路径，关键句末可重建完整已知模型。也可从局部 `Offset → Next Offset` 扩展到 `Position → Read → Advance` 再到 Pull loop；每层须遵循上节的增量与证据要求，不补造缺失环节。
- **显式呈现必要边界。** 容易过度推断时，可用 Known / Derived / Unknown 小块或依据类型标注突出限制，也可融入自然段落；不强制每句三栏。
- **本句分析动作。** 当前句确实用到可迁移的分析或设计方法时，按上节在末尾命名并说明适用时机，把方法从当前内容中抽象出来；没有真实方法增量时省略。
- **长度随内容变化。** 按上节三档决定展开程度：关键句可以有较多编号、图和多层抽象，过渡句三五行即可；各层内部用自然、连续的解释，不写成字段报表或无增量的铺陈。
- **结尾保留可靠停点。** 默认用一行给出 `Current revealed position`，包括 Section / Page、paragraph、sentence、normalized_range、effective_kind、degradation 与当前单元的 exact re-read 状态，格式如 `page-N · ¶P · sS · [start,end) · sentence · degradation none · exact-read complete`。`complete`、`section_complete`、`coverage.source_complete` 描述的是枚举流，不证明本会话已读到哪里，不作为停点展示。完整 hash 和工具参数留在会话绑定中，不要求用户每句阅读。

## 完整推导示范（虚构）

以下两句话是自包含的虚构材料，不是 Kafka 或任何论文原文，不引入真实阅读的未读信息。示范只解释上面的 v2 **内部推导颗粒度**：哪些前提和中间连接不能省；它不是前台固定标题、固定层数、固定字数或每句必须套用的模板。

已知前文：

> 每发起一次请求，都会产生固定开销 C（C > 0）；这项开销不随该请求携带的记录条数变化。

当前句：

> 客户端可以在一个请求中提交多条记录。

只说“这是批处理，可以提高性能”，就省略了这两句话之间最重要的连接。下面从已有信息展开，不先给出未经限定的性能结论。

**先看，前文把开销和什么联系起来。**

前文说的是“每次请求”，不是“每条记录”。所以，要计算这项开销发生多少次，应当先数请求次数，而不能直接数记录条数。记录本身可能还有处理成本，但前文给出的 C 只代表请求的这一项固定开销，两者不能混在一起。

**接着看，当前句改变了哪一项。**

“一个请求中提交多条记录”没有说待提交的记录变少了，也没有说记录不再需要处理。它允许改变的是这些记录怎样分配到请求中。因此，需要比较的是：完成相同记录提交，是否能够使用更少的请求。

为看清这一点，取同样三条记录甲、乙、丙，假定它们可以合在一个请求中提交。这是说明用的比较假设，不是从当前句推出任意记录都能合并。

分别提交时，三个请求各携带一条记录；合并提交时，一个请求携带全部三条。两种方式提交的记录相同，变化的是请求次数：三次变为一次。

**再把这个变化接回前文，而不是直接跳到“更快”。**

前文已给出每次请求的固定开销 C，并说明它不随记录条数变化。因此，分别提交时，这项开销的总量是 `C + C + C = 3C`；合并提交时是 `C`。减少的是重复发生的请求固定开销，不能把它误说成每条记录自身的处理工作也减少了。

**现在才能说明，“摊薄”具体意味着什么。**

分别提交时，每条记录独自承担一次 C，平均固定成本为 C；合并提交时，三条记录共同承担一次 C，平均固定成本为 `C / 3`。这项开销没有消失，而是由多条记录共同承担；由于 C > 0，在这个比较中每条记录分摊的这一部分成本确实降低了。

所以，当前能够得到的结论是：在记录可合并、请求固定项不随记录数变化的条件下，把相同记录合到更少请求里，可以减少重复发生的固定开销，并降低平均到每条记录上的这部分成本。

**最后检查，结论还能扩大到哪里。**

两句话没有给出其他处理成本、合并产生的额外工作或等待时间。因此，这个推导只能解释固定开销这一项，不能证明总处理时间一定更短、每条记录的延迟一定更低，也不能确定最佳批量大小。这些不是用“提高性能”四个字就能补齐的信息。

这段示范的关键是保持依据与连接完整：辨认开销对象，保持比较的记录相同，找出请求次数的变化，再按已有条件推导固定项成本，最后限定结论。实际分析中，只展开当前理解真正需要的连接；删去重复，不删去成立所需的理由。

## 输出前的小检查

AI 在输出前检查：原文是否忠实？关键判断的依据和连接是否完整？有没有越过已知范围？有没有可以删掉的重复或含糊表达？发现问题就在当前解释中修正，不把自检表发给用户，不另开评分或验收任务。

对有实质信息的单元再检查：是否只解释了一个中心词，漏掉其他关键限定？当前句究竟改变了什么，而不是仅仅“与前文有关”？每次回接和每张图是否增加理解？Unknown 是否指出具体结论的证据缺口？若答案只剩翻译、复述和泛化总结，在当前已揭示范围内补齐理由；不能通过多读一句补足分析。低信息过渡仍可简短，不硬造模型增量。

再从学习目标检查：读者能否看出每个结论由哪个线索触发、依据是什么？箭头背后的前提是否写出？前文提出的问题在本句被回答时是否交代了？限定词强度是否在推理中保持一致？

用户说“没理解”时，优先修复遗漏前提、抽象术语、层次混淆或表达跳步；不要改成考用户。澄清只使用已读范围，不把追问视为推进下一句的授权。

## Source 边界

普通首次阅读只用已揭示前文与当前单元作为论文证据。默认可解释理解当前句必需的通用概念，如术语定义、基础数学或一般系统概念；就地标明它是背景或说明性假设，不归因于作者，不逐项请求许可。目标论文特有的后续机制、证明、实验结果，以及现代实现细节，不因模型已知就成为允许背景。现代版本对照或外部检索须另获授权并与当前分析分开；用户已有的更窄限制优先，额外背景与限制保存在阅读状态。

一次“下一句”默认取得一个 canonical SourceUnit，并精确回读。保留 provider 的 kind、顺序、fragment 和 locator；不根据标点自造新 identity，不为凑完整句批量读取后文。图表或公式只在当前内容确有需要时核对原始视觉；无法避免越界暴露时停止并记录，不能假装没看见。

原文返回不完整、identity 不符或 locator stale 时，不用记忆、搜索或二手分析补齐。工具细节按需查 [reading-mcp 集成](../integrations/reading-mcp.md)，不是每句的额外前置阅读。

## 连续阅读与范围

本句讲完只停止本次输出；同一会话中下一次“下一句”即可继续当前已授权范围。追问、换说法、回看不改变已揭示位置，也不触发重测。默认不新开 Session、不要求换 conversation。

如果下一单元超出已授权范围，简短说明边界并请求继续范围；用户同意后由 Agent 保存范围变化再读。历史停点、已消费的一单元授权不被本协议自动重新激活。

按[会话与进度](reading-sessions.md)保留本会话的位置和必要记录；不生成交接摘要、模型快照或恢复资产。暂停后在原会话继续，仓库维护另开会话。

## 版本与历史

本次修订保持 v2 id，具体内容由 commit 固定。退役流程见[工程工作流](../workflows/issue-driven-workflow.md#已移除的流程)，历史字节和结果见[历史引用](../README.md#历史引用)；旧绑定不自动升级。

新 Session 记录本契约 id 和来源 commit；加载顺序与旧会话显式切换统一见[阅读状态](reading-sessions.md#规则版本加载)。Source identity、已读位置、未知项和范围不因文档修订改变。

CI 只检查结构；这份契约是否落实，直接在真实逐句分析中看误读、跳步、冗余与边界，按具体问题修正。正常阅读不设额外准入验收。
