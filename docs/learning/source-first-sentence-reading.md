# Source-First 逐句分析协议

当前契约：`source-first-analysis/v2`。唯一目标是提供基于已知信息、逻辑连贯、层层讲透的 AI 逐句分析，让用户通过持续阅读自然学习分析方法。

## 唯一日常流程

```text
当前原文 → 忠实释义 → 有依据的连贯分析 → 当前句结束
```

用户无需作答或刻意练习。本仓库已删除训练模式、题目、评分、预测锁定及盲测流程，不保留可选训练入口。复杂度放在 AI 分析的认真程度上，不放在用户操作上。

## 分析必须做到什么

**先说清对象和字面意思。** 原文先行，外语随后给忠实中文翻译；中文原文不重复翻译。保留“可能、通常、仅在”等限定。首次必要术语就地解释，指代不让用户猜。翻译不夹带自己的机制解释。

**关系要具体。** 联系真正有助于理解当前句的已读前文，指出当前句在哪个地方承接、对比、回答、限制或闭合此前机制；不能只贴“因果、转折、解耦”等标签。前文回接范围由当前句的认知作用决定：普通句只接必要局部；关键机制句如果让此前多个零散设计第一次闭环，就应把这些已揭示前文重新拼成完整路径。允许为了形成新的整体模型重画已有局部，但每次重组都必须带来新的理解增量，不能为了显得完整机械复述。

**逐层承接，不跳步。** 从当前原文和必要前文出发，先澄清对象与线索，再解释所需的前提或区别，最后得到当前结论；后一层使用前一层已经说明的信息。每层解决一个真实的理解疑问，不罗列互不衔接的结论。重要推导说明“为什么能从这里走到那里”，额外前提显式提出；不能用“显然”“本质上”或一根箭头跳过理由，不能把先后顺序说成因果。

这里的“详细”是把依据、必要前提和关键连接讲完整，而不是增加无关背景；不能用翻译、结论或术语标签替代这段显式推导。详细度优先花在**当前句内部**：如果一句同时包含条件、观察、限定、术语和结论，就把理解这句话所需的各部分分别讲清，再说明它们怎样连起来；不要只解释其中一项后就直接收束。结论是推导后的收束，不能把中间理由留给用户补。信息不足时，讲清缺少什么及为何暂不能继续推导，不补造答案。

**每句有真实增量。** 说明当前多知道了什么、修正了什么，或仅起什么结构作用。普通过渡简短，关键机制讲透；不强迫每句生成完整机制链、L0/L1/L2 标签或“思维方法总结”。方法自然体现在分析里。

**边界清楚但不做报表。** 原文明说、有限推论、尚未确定分别用自然语言交代即可，不要求每句列三栏。每个重要箭头须能追到已读 Source 或注明推论及其条件。不要为了读起来流畅而编出作者动机、隐藏困难或关闭开放问题。

**让理解顺畅。** 用连贯短段落和必要箭头，不堆无意义的标题、术语或重复总结。默认增量骨架用于让认知变化可见，但每一层内部仍用自然语言展开，不能写成字段报表。主动补齐必要连接，不让用户再猜指代、补前提或翻找上下文；删去无助于当前理解的背景。简单的是阅读流程，不是被压缩的推导。方法体现在具体分析中，不再追加练习。目标是减少可避免的理解摩擦，不隐藏材料本身的困难，也不把阅读流畅当作能力提升证明。

## 默认呈现：首版高密度机制闭环风格

默认前台呈现采用 Kafka 首轮真实阅读中已经验证过的**高密度、动态编号、机制闭环型逐句分析**。它不是固定字段表，也不是尽量隐藏结构的短文；关键句要把当前 SourceUnit 放回已知系统模型中，必要时重组较早已读前文、画 ASCII 路径并明确闭环。低信息过渡句仍保持短。

典型节奏是：

```text
论文 / Section / 可靠正文序号（如 durable state 可恢复）

当前原文
必要的 PDF 抽取修正说明
中文翻译

一句总判断：
当前 SourceUnit 在论证中做了什么

1. 当前句触发的第一个真实问题
2. 第二个真实问题
3. ...
   → 每个编号由当前句的信息和机制关系决定
   → 不是固定“字面/关系/增量/模型”字段

必要时：
- 重组此前已揭示机制
- 画局部或端到端 ASCII 路径
- 给出 Before / After、Problem → Mechanism → Effect
- 区分 Known / Derived / Unknown
- 提炼真正存在的可迁移设计方法

最后：
Current revealed position
```

具体要求：

- **原文必须先行。** 原文来自当前 exact re-read 的 canonical SourceUnit。PDF 抽取只有换行、断词、空白等版式噪声时，可以做不改变字词和语义的排版整理；若需要修正展示，要明确说明是版式还原，不能补词、改写或把多个 provider unit 合成一个“更完整”的句子。
- **位置要可靠，不猜正文计数。** 可展示论文、Section、Page、paragraph、sentence、normalized_range、effective_kind、degradation；“第 N 条正文句 / Section 总第 M 条正文句”只有 durable state 或可靠计数可恢复时才展示，缺失时省略。
- **先给当前句一个总判断。** 在详细拆解前，用一两句话说明当前句的论证作用，例如“把前面几条机制串成循环”“把 OS 能力落回 Kafka 实现”“把 baseline 成本变成可比较数字”。这个判断必须由当前句和已揭示前文支撑。
- **动态编号，不固定字段。** 对有实质信息的 SourceUnit，按当前句真正产生的理解问题动态生成 `1、2、3...`。编号标题可以是“前面的 next offset 现在真正用起来了”“Index → Segment 的映射”“但当前不能推出 Broker 完全无状态”等；不能机械填 `字面 / 前文 / 增量 / 模型` 五个槽位。
- **当前句内部该拆的都拆。** 同一句若同时包含条件、对象、术语、路径、数量、限定和结论，要分别讲清，并说明它们怎样连接。对 `since / because / therefore / but / specifically` 等关系，按成立所需的中间步骤展开，不能用一根箭头跳过理由。
- **有目的地重组已读前文。** 当前句若只是局部增量，只接局部；当前句若让多个早先 Source 第一次形成完整协议、数据路径或生命周期，就把这些已揭示机制重新拼起来。允许同一概念在不同抽象层次重复出现，例如先解释局部 `Offset → Next Offset`，再放入 `Position → Read → Advance`，最后放进完整 Pull loop；每次重复都必须增加新的结构理解。
- **ASCII 图和箭头是默认工具。** 当空间关系、层级关系、数据流、生命周期、Before/After 或端到端路径用图更清楚时，主动画简洁 ASCII。箭头只表示已经解释过的关系，不能代替理由；图必须来源于当前或此前已揭示 Source，说明性假设要显式标明。
- **关键机制句要追求闭环。** 当 Source 足够时，可以按实际内容形成 `Problem → Baseline → Cost → Existing Capability → Decision → Mechanism → Effect → Boundary`、`Data Structure → Address → Protocol → Progress` 等闭环，但不能为了套框架补不存在的环节。
- **整体模型可以在关键句结束时重建。** 若当前句让此前零散机制第一次连成端到端路径，可以重画当前已知完整模型，让读者看到“这一句怎样改变整个理解”，而不是只给一句局部解释。过渡句不强制这样做。
- **Known / Unknown 边界要主动指出。** 特别是当前句很容易诱发进一步推断时，明确写出当前已知什么、有限推论是什么、最容易过度推到哪里。可以使用 `Known / Unknown` 小块，也可以自然写进正文；不能把观察结果升级为严格因果证明，也不能把未来机制倒灌进来。
- **思考方法可以单独成节。** 当前句确实形成了可迁移设计方法时，可以保留“这里可以学习什么思考方法”，并把方法从当前机制中抽象出来；没有真实方法增量时省略。
- **高密度不等于冗长。** 关键机制句可以有较多动态编号、图和多层抽象；纯导航、重复确认或低信息句保持简短。详细度服务于理解，不服务于固定字数。
- **避免两种漂移。** 一种是固定字段报表化；另一种是没有机制增量的散文式铺陈。历史首版风格的核心是“结构明显，但结构由当前机制生长出来”。
- **结尾保留完整停点。** 默认给 `Current revealed position`，至少记录可靠的 Section / Page / paragraph / sentence / normalized_range / effective_kind / degradation；完整 hash 和工具参数仍留在 durable state，不要求用户每句阅读。

## 完整推导示范（虚构）

以下两句话是自包含的虚构材料，不是 Kafka 或任何论文原文，不引入真实阅读的未读信息。示范只解释上面的 v2 **内部推导颗粒度**：哪些前提和中间连接不能省；它不是前台固定标题、固定层数、固定字数或每句必须套用的模板。

已知前文：

> 每发起一次请求，都会产生固定开销 C（C > 0）；这项开销不随该请求携带的记录条数变化。

当前句：

> 客户端可以在一个请求中提交多条记录。

只说“这是批处理，可以提高性能”，就省略了这两句话之间最重要的连接。下面从已有信息展开，不先给出未经限定的性能结论。

**先看，前文把开销和什么联系起来。**

前文说的是“每次请求”，不是“每条记录”。所以，要计算这项开销发生多少次，应当先数请求次数，而不能直接数记录条数。记录本身可能还有处理成本，但前文给出的 C 只代表请求的这一项固定开销，两者不能混在一起。

**接着看，当前句改变了哪一项。**

“一个请求中提交多条记录”没有说待提交的记录变少了，也没有说记录不再需要处理。它允许改变的是这些记录怎样分配到请求中。因此，需要比较的是：完成相同记录提交，是否能够使用更少的请求。

为看清这一点，取同样三条记录甲、乙、丙，假定它们可以合在一个请求中提交。这是说明用的比较假设，不是从当前句推出任意记录都能合并。

分别提交时，三个请求各携带一条记录；合并提交时，一个请求携带全部三条。两种方式提交的记录相同，变化的是请求次数：三次变为一次。

**再把这个变化接回前文，而不是直接跳到“更快”。**

前文已给出每次请求的固定开销 C，并说明它不随记录条数变化。因此，分别提交时，这项开销的总量是 `C + C + C = 3C`；合并提交时是 `C`。减少的是重复发生的请求固定开销，不能把它误说成每条记录自身的处理工作也减少了。

**现在才能说明，“摊薄”具体意味着什么。**

分别提交时，每条记录独自承担一次 C，平均固定成本为 C；合并提交时，三条记录共同承担一次 C，平均固定成本为 `C / 3`。这项开销没有消失，而是由多条记录共同承担；由于 C > 0，在这个比较中每条记录分摊的这一部分成本确实降低了。

所以，当前能够得到的结论是：在记录可合并、请求固定项不随记录数变化的条件下，把相同记录合到更少请求里，可以减少重复发生的固定开销，并降低平均到每条记录上的这部分成本。

**最后检查，结论还能扩大到哪里。**

两句话没有给出其他处理成本、合并产生的额外工作或等待时间。因此，这个推导只能解释固定开销这一项，不能证明总处理时间一定更短、每条记录的延迟一定更低，也不能确定最佳批量大小。这些不是用“提高性能”四个字就能补齐的信息。

这段示范的关键是保持依据与连接完整：辨认开销对象，保持比较的记录相同，找出请求次数的变化，再按已有条件推导固定项成本，最后限定结论。实际分析中，只展开当前理解真正需要的连接；删去重复，不删去成立所需的理由。

## 输出前的小检查

AI 在输出前检查：原文是否忠实？关键判断的依据和连接是否完整？有没有越过已知范围？有没有可以删掉的重复或含糊表达？发现问题就在当前解释中修正，不把自检表发给用户，不另开评分或验收任务。

用户说“没理解”时，优先修复遗漏前提、抽象术语、层次混淆或表达跳步；不要改成考用户。澄清只使用已读范围，不把追问视为推进下一句的授权。

## Source 边界

普通首次阅读只用已揭示前文与当前单元。必要的通用概念可以在明确允许的背景范围内说明，但不能据此替代目标论文事实。现代版本对照或外部检索须另获授权，和当前论文分析分开。

一次“下一句”默认取得一个 canonical SourceUnit，并精确回读。保留 provider 的 kind、顺序、fragment 和 locator；不根据标点自造新 identity，不为凑完整句批量读取后文。图表或公式只在当前内容确有需要时核对原始视觉；无法避免越界暴露时停止并记录，不能假装没看见。

原文返回不完整、identity 不符或 locator stale 时，不用记忆、搜索或二手分析补齐。工具细节按需查 [reading-mcp 集成](../integrations/reading-mcp.md)，不是每句的额外前置阅读。

## 连续阅读与范围

本句讲完只停止本次输出；同一会话中下一次“下一句”即可继续当前已授权范围。追问、换说法、回看不改变已揭示位置，也不触发重测。默认不新开 Session、不要求换 conversation。

如果下一单元超出已授权范围，简短说明边界并请求继续范围；用户同意后由 Agent 保存范围变化再读。历史停点、已消费的一单元授权不被本协议自动重新激活。

暂停、自然段落/机制收束、交接、故障或范围变化时保存 [一份阅读状态](reading-sessions.md)。操作位置与分析摘要可以分区保存在同一记录；只有摘要确实过长时才拆出一份引用式资产。

## 版本与历史

v2 删除 v1 保留的可选训练入口，并强化逐层承接。旧 Profile / Pilot 已从当前文件树移除；历史字节和结果仍在原 commit，索引见 [历史引用](../README.md#历史引用)。旧绑定按记录的 commit + path 读取，不要求恢复已删除文件或重跑旧流程。

新 Session 记录本契约 id 和来源 commit。旧 Session 在用户授权采用新流程时，只需在同一阅读状态记一次 `旧绑定 → source-first-analysis/v2`、生效 locator 和来源 commit；Source identity、已读位置、未知项和范围保持不变，不要求重读或 fresh 测试。用户目标决定当前授权，不允许静默改写既有记录。

CI 只检查结构；这份契约是否落实，直接在真实逐句分析中看误读、跳步、冗余与边界，按具体问题修正。正常阅读不设额外准入验收。
