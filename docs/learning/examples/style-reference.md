# 用户确认的风格参考（维护用）

针对 [#43](https://github.com/liqiangcc/paper-reading-lab/issues/43)，用户在维护会话提供并确认了 [Kafka Consumer Group 完整样本](kafka-consumer-group-user-sample.md)。该文件保留用户提供的 16 节分析及停点，不先压缩成规则。收录的是风格偏好证据，不是重新核验的论文事实或 canonical Source；样本的前文声明与 locator 仅作历史引用。

## 怎样参考

值得迁移的是理解推进：逐一展开 `one or more`、`jointly`、`i.e.`、`only one`、`within the group` 的作用；区分成员、共同任务与交付约束；回接已知 Partition/Offset 后指出未连接关系；说明结论适用范围，再重建整体理解。

不要复制 16 节、图数、篇幅或 Kafka 词汇。样本第 3/4/10/11/16 节存在主题相近的重述，实际输出只有解释了新的层次才保留。认可体验不等于把所有重复都写成强制规范。

样本也不是不可修正的事实标准。例如“正常 delivery”是分析限定，不是引文显式给出的条件；`only one` 的表述不能升级为跨重试、跨时间的 exactly-once 保证。消息分配图只示意组内归属，不代表分配算法、顺序或性能已获证明。保存原样不等于为其中全部判断背书。

## 证据与加载边界

真实样本不在日常首次阅读必读清单内，也不自动装入其他论文上下文。维护任务或用户明确授权查看该样本时才读取；对目标论文未读部分的暴露仍需遵守 Source 边界。不得用样本重建跨会话前文，不得复制其 locator 为当前停点。

日常校准使用同一协议 commit 下的两份自包含虚构示范：[机制闭环](mechanism-closure.md)、[概念与论证闭环](argument-closure.md)。二者示范推导深度，均不是当前论文的事实。
