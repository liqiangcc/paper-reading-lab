# 会话与进度

## 一篇论文一个原始会话

在该论文的专属阅读会话中持续读取、分析、追问和回看。继续阅读依赖本会话保有的原文、论证过程和未决问题，不从 Issue 的位置或摘要重建理解。仓库治理和规则修改放在独立维护会话，不把维护会话转为论文续读会话。

新会话收到“继续论文 #N”时说明边界，请用户回到原阅读会话；不扫描历史 comments、聊天日志，不组装 handoff，不用精确回读重建跨会话前文。确实要从头重新阅读须由用户明确提出，作为新的阅读过程，不冒充原有理解的恢复，也不自动清除历史暴露记录。

同一会话不保证无限上下文。关键前文因压缩或其他原因不可用时，说明缺失并停止依赖它作后续推论；不把“仍是原会话”当完整性证据，也不启动摘要恢复流程。

## 会话内保留什么

- 论文/Revision 与 reading-mcp document、content/normalized hash、segmentation identity。
- 当前授权范围、实际已揭示位置、完整 TextLocator。
- 未完成单元及阶段（如有），已完成位置。
- 实际加载的分析协议 id、完整来源 commit 和 path。
- 本会话中的前文、推导连接、用户追问和未决问题；不另建持久化累计模型。

这些信息由 AI 负责，不要求用户填写字段或重复粘贴规则。新段落不能使本会话仍可用的较早机制失去作用；分析要回接相关前文，不只回接紧邻上一句。

## 已揭示与已完成

单元 N 返回后即记录其实际暴露及待完成阶段；精确回读并输出分析后才标记完成。回读失败或输出中断时，只在原会话处理同一 N，不把它用作已完成 anchor 取 N+1。当前上下文不能确认目标或完成情况时先停止，不猜测跳过。

## 何时保存

Issue 保存论文入口、必要进度和问题，便于人查看，不提供恢复能力。用户要求保存、暂停或范围/故障发生实质变化时，记录已知身份、授权边界、可靠停点、完成/未完成情况及必要问题即可；不强制按自然段保存，不附可执行续读脚本、模型快照或交接摘要。

更新已有正文前重读并检查是否有并发变化，发现冲突不覆盖；写后回读确认。旧评论保留为历史，当前正文明确其非执行用途，不再维护完整 READING STATE 指针协议。进度记录不能授予另一会话续读权限。

## 规则版本加载

首次开始前读取当前操作规则（AGENTS、Skill、Source Adapter、本页），以及已核验 main 的分析协议和同 commit 示范，在本会话记录来源。之后复用本会话实际保有的材料，不每句加载。

原阅读会话采用协议更新时，依据用户授权明确新旧版本和生效位置，不静默切换或重写历史；没有可靠版本或内容时不猜测。已有固定分析协议负责分析质量，现行操作规则负责会话、工具与范围边界；旧协议中的跨会话恢复/交接步骤不再执行。

## 范围与历史

授权范围、Source identity 不因暂停、回看或文档简化改变。下一单元越界前先获用户同意；一条分析结束不是论文读完。

旧 Session、失败、污染、契约绑定及恢复记录只供追溯；取消恢复能力不把历史失败改为成功，也不将旧 next_action 重新激活。
